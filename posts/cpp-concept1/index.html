Inline#

  1. 매크로를 이용한 함수의 인라인화는 전처리기에 의해서 처리되지만 keywokd inline을 이용한 함수의 인라인화는 컴파일러에 의해서 처리가 된다. 따라서 컴파일러는 함수의 인라인화가 오히려 성능에 해가 된다고 판단할 경우, 이 키워드를 무시해버리기도 한다. 또한 컴파일러는 필요한경우 일부 함수를 임의로 인라인 처리하기도 한다.
#define SQUARE(x) ((x)*(x))

int main()
{
	int result = SQUARE(5);
}

위처럼 C에서는 전처리 과정에서 SQUARE를 ( 5 x 5 )로 치환한다. 위 코드처럼 매크로 함수는 매개변수의 타입에 구애를 받지 않으나 타입 체크와 디버깅에 어려움이 있어 안전하지 않을 수 있다는 단점이 있다.

inline int sqaure(int x) {
	return x * x;
}

int main()
{
	int result = square(5);
}

위처럼 inline 함수를 사용하면 함수의 타입 검사가 이루어지며 안전하게 함수 호출을 인라인 할 수 있으나 컴파일러가 인라인화를 보장하지 않을 수 있고 큰 함수나 복잡한 함수에 대해서는 인라인화가 되지 않는다.

namespace#

1. :: 는 범위 지정 연산자라고 하며 이름공간을 지정할떄 사용한다.

지역변수의 이름이 전역변수의 이름과 같을 경우, 전역 변수는 지역변수에 의해 가려진다.

int val = 100;

int SimpleFunc(void)
{
	int val = 20;
	val += 3; // local variable
	::val += 7; // global variable
}

True는 1 이 아니며 false 역시 0이 아니다. 이 둘은 참과 거짓을 표현하기 위한 1byte 크기의 데이터일 뿐이다.

참조자의 선언 가능 범위 :

  1. 참조자는 유효 변수에 대해서만 선언이 가능하고, 선언됨과 동시에 누군가를 참조해야한다.
  2. 참조자는 본디 , 변수에 또 다른 이름을 붙이는 것이기 때문에 상수를 대상으로 참조자를 선언할 수는 없다. 뿐만 아니라, int &ref 와 같이 미리 참조자를 선언했다가 누군가를 참조하는 것은 불가능하다.
  3. int &ref = NULL 참조자를 선언하면서 NULL로 초기화하는것도 불가능하다.
  4. 참조자는 포인터와 달리 한번 초기화 되면 다른 변수를 참조할 수 없다. 보통 변수 자체로 사용한다.
#include <iostream>
using namespace std;

void SwapByRef2(int &ref1, int &ref2)
{
	int temp = ref1;
	ref1 = ref2;
	ref2 = temp;
}

int main(void)
{
	int val1 = 10;
	int val2 = 20;

	SwapByRef2(val1, val2);
	cout << "val1: " << val1 << endl;
	cout << "val2: " << val2 << endll
}

참조자의 단점 :

int num = 24;
HappyFunc(num);
cout << num << endl;

위 코드에서 C 언어의 관점에서는 무조건 24 가 출력된다. 하지만 Cpp 는 아래와 같은 경우가 발생할 수 있다

// 24 출력
void HappyFunc(int prm) { ... }

// 24가 출력될 수 도있고 ref 값을 변경하면 num이 다른 값으로 출력될 수 있따
void HappyFunc(int &ref) { ... }

따라서 C언어는 함수의 호출문장만 보고도 값이 변경되지 않음을 확인할 수 있지만, cpp에서는 이것이 불가능하다. 따라서 위 HappyFunc는 아래와 같이 사용하는게 바람직하다

void HappyFunc(const int &ref) { ... }

int RefRetFunTwo(int &ref)
{
	ref++;
	return ref;
}

위 함수의 경우에는 int num2로 값을 받을 수 있으나 int &num2로는 받을 수 없다. 반환 값은 상수 r-value 나 다름 없기 때문이다.

int& RetuRefFunc(int n)
{
	int num = 20;
	num += n;
	return num;
}

위의 함수에서는 지역변수 num에 저장된 값을 반환하지 않고, num을 참조의 형태로 반환하고 있다 . 따라서 다음 함수를 호출하고 나면 int &ref = returRefFunc(10) 과 같이 지역 변수 num 에 ref 라는 또 하나의 이름이 붙게된다. 따라서 위의 함수처럼 지역변수를 참조형으로 반환하는 일은 없어야 한다.

int num = 20 + 30; 여기서 20과 30은 프로그램상에서 표현되는 숫자이다 . 이를 리터럴 혹은 리터럴 상수라고한다. 그리고 이들은 암시적으로 존재하며 다음 행으로 넘어가면 존재하지 않는 상수라고도 한다. 그러면 const int &ref = 30 은 맞는 코드일까? 이는 숫자 30이 메모리 공간에 계속 남아있을 떄에나 성립이 가능한 문자이다. 따라서 C++에서는 위의 문장이 성립될 수 있도록 const 참조자를 이용해서 상수를 참조할때 임시변수라는것을 만든다. 그리고 이 장소에 상수 30을 저장하고선 참조자가 이를 참조하게 한다.

#include <iostream>

int main()
{
    int *ptr = new int;
    int &ref = *ptr;
    ref = 20;
    cout << *ptr << endl;
    return 0;
}
특성 구조체 (Structure) 열거형 (Enumeration)
목적 다양한 데이터 타입을 하나의 단위로 묶기 위해 사용 정수 값에 의미 있는 이름을 부여하기 위해 사용
데이터 타입 서로 다른 데이터 타입을 가질 수 있음 기본적으로 정수형으로 내부적으로 처리됨
메모리 할당 모든 멤버 변수를 위한 메모리 공간이 할당됨 열거형 요소는 상수로, 메모리 공간을 따로 할당하지 않음
사용 용도 복합 데이터 구조를 표현하기 위해 사용 상수 집합을 정의하여 코드의 가독성 향상
접근 방식 구조체 변수를 통해 멤버 변수에 접근 열거형 변수는 열거형에서 정의된 값 중 하나를 가짐
내부 표현 멤버 변수의 데이터 타입에 따라 다름 내부적으로 정수 값으로 표현됨

생성자#

  1. 생성자도 함수의 일종이기 때문에 overloading이 가능하다
  2. 생성자도 함수의 일종이기 떄문에 default value를 설정할 수 있다.

Member initializer#

class Rectangle 
{
private :
	Point upLeft;
	Point lowRight;
public:
	Rectangle(const int &x1, const int &y1, const int &x2, const int &y2)
		: upLeft(x1, y1), lowRight(x2, y2); // member initializer
		
}

위 코드에서 upLeft, lowRight를 Member initialize라고 하며 이것이 의미하는 바는 다음과 같다

객체 upLeft의 생성과정에서 x1과 y1을 인자로 전달받는 생성자를 호출하라 객체 lowRight의 생성과정에서 x2와 y2을 인자로 전달받는 생성자를 호출하라

참조자 vs 포인터#

클래스 안에 아래와 같은 함수가 포함되어있다고 가정해보자

SoSimple& GetThisReference() {
	return *this
}

SoSimple* GetThisReference() {
	return this
}

위 함수를 보면 this를 반환하는 포인터 리턴 함수는 class 객체에 대해 직접 접근할 수 있으며 이는 객체를 직접 관리하거나 여러개의 객체를 배열로 사용할 수 있다. 반면 *this를 반환해 참조자를 반환하는 함수는 객체 자체에 대한 참조를 얻어내 함수의 반환값을 일반 변수로 받아내 사용할 수 있다. 하나의 생성자로 여러개의 객체 생성 가능 this = 이 클래스에 대한 메모리 주소

복사 생성자#

아래는 cpp에서 변수와 참조자를 선언 및 초기화하는 방식이다

int num = 20;
int &ref = num;

int num(20);
int &ref(num);

#include <iostream>
using namespace std;

class SoSimple
{
    private:
        int num1;
        int num2;
    public:
        SoSimple(int n1, int n2) : num1(n1), num2(n2) { 
            cout << "생성자 호출 " << endl;
            
        }
        SoSimple(SoSimple &copy) : num1(copy.num1), num2(copy.num2) {
            cout << "복사 생성자 호출 " << endl;
        } // 복사 생성자
        
        void ShowSimpleData()
        {
            cout << num1 << endl;
            cout << num2 << endl;
        }
        ~SoSimple() {
            cout << "소멸자 호출 " << endl;
        }
};


int main(void)
{
    SoSimple sim1(15, 20);
    SoSimple sim2 = sim1;
    sim2.ShowSimpleData();
    return 0;
}

위 코드를 cpp에 초기화 하는 방식으로 대입해보면 아래와 같다.

SoSimple sim2=sim1;
SoSimple sim2(sim1);

그런데 위의 과정을 실행하면 sim2의 생성자 호출에 대해서는 언급하지 않는다. sim2의 로직을 확인해보면서 분석해보자

  1. SoSimple형 객체를 생성해라
  2. 객체의 이름은 sim2로 정한다
  3. sim1을 인자로 받을 수 있는 생성자의 호출을 통해서 객체 생성을 완료한다.

즉 위의 객체 생성문에서 호출하고자 하는 생성자는 다음과 같이 SoSimple 객체를 인자로 받을 수 있는 생성자이다. 위의 코드에서 복사 생성자의 코드 없이도 복사가 진행되는것을 경험할 수 있는데 어떻게 가능한것이냐 하면 컴파일러가 디폴트 복사 생성자를 생성해주기 때문에 따로 작성하지 않아도 복사가 진행된 것이다.
