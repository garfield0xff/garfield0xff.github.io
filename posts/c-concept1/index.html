혼자 공부하는 C 언어 1장부터 11장까지의 내용을 개인적으로 복기하기 위해 정리한 내용입니다.

Program#

1. Program 은 명령어의 로직을 설계하고 나열한 것이다.
2. C언어는 하드웨어에 상관없이 유닉스를 개발하기 위해 설계되었다.
3. Compile (빌드) 은 Source 를 컴파일러를 통해 기계어로 만드는 과정이다. ( Decomplier )
4. gcc 는 어셈블리어를 기계어로 porting 하는 기능도 포함하기 때문에 어셈블러의 기능을 포함한 컴파일러라고도 생각할 수 있다.
5. visual studio는 IDE 이자 Compiler(MSVC) 의 기능을 포함하고 있다. -> 책에서는 컴파일러중 하나라고 표현하고 있지만 명확하게는 Microsoft Visual C 의 컴파일러의 기능을 포함한 IDE가 정확한 표현이다.

Compile Process#

1.전처리 : preprocess는 전처리 지시자에 따라 소스 파일을 가공하는 과정. 예를들어 전처리 과정이 지나면 #include <stdio.h>가 lib.c 파일을 불러 Rom 메모리 Text section에 추가함 따라서 전처리 과정은 #include 혹은 #define 혹은 매크로 같은 preprocess 함수를 텍스트로 치환해 코드해 포함하는 과정이라 할 수 있음. objdump 를 활용하여 c 에서 i 를 확인해볼때 Text 섹션이 증가한 것을 확인 할 수 있다.
2. 컴파일 : 전처리가 끝난 파일을 컴파일하면  .s (assembly) 파일이됌 이 어셈블리 파일을 어셈블 과정을 진행하면 .o 개체파일이 형성됌 이 개체파일은 함수 이름 변수 이름등 외부 심볼등의 정보가 포함된 심볼 테이블들이 있으며 독립적으로 사용될 수 없으며 링크할 Startup Code (C-Rumtime Libarary) 가 필요함
3. 링크 : CRT와 개체파일이 링크되어 운영체제에서 인식할 수 있는 실행파일로 변경한다.
   CRT 는 Stack Frame, Stack Pointer 등 스택과 힙등을 관리하며 운영체제를 통해 영역을 확장, main 함수를 실행한다.

printf#

1. \r \n  window에서는 \r과 \n 을 \n에 하나로 통합해 사용하고 있지만 \r은 커서를 맨앞으로 옮기고 \n은 한줄 밑으로 옮긴다는것을 구분해야함 ex) print("Hello\rbaby") = baby
+ 출력문은 type의 값을 임시버퍼를 활용해  모든 값들을 문자열로 할당함 따라서 char 자료형의 정수 값을 출력해도 ASCII 문자로 나오는것이 그 이유, 나머지 자료형들도 다 문자열로 출력된다고 할 수 있다.

Const#

1. 상수는 값을 바꿀 수 없다 -> L-value로 다시 사용할 수 없다로 생각하자
2. 10은 정수 상수, 10.0 은 실수 상수, 'a'는 문자 상수 "a" 는 문자열 상수 -> 상수라는 표현보다 수정되지 않는 메모리 영역을 참조하는 r-data로 생각하는게 좋은 것 같다. r-data는 운영체제나 로더가 관리하며 이 영역을 읽기전용으로 설정하기 때문에 이 데이터를 변경할 경우 오류를 발생시킨다.
3. 정수 상수의 양수는 4바이트 크기의 2진수로 음수는 2의 보수로 컴파일한다
4. 실수는 IEEE 754 표준의 double 형식에 따라 번역되며, 첫 비트는 부호비트, 이후 11개 비트는 지수부, 나머지 52비트는 소수부로 나타낸다. 따라서 실수뿐만 아니라 모든 데이터 구조에 해당 첫 비트가 부호비트에 사용되기때문에 signed는 unsigned 보다 1 / 2의 expression range를 가진다.

Variable#

1. 변수 선언으로 메모리에 저장 공간을 확보하며, 대입 연산자로 변수 값을 초기화하거나 저장한다. 초기화하지 않은 변수에는 쓰레기 값이 들어있다 -> 전역 변수는 프로그램의 Data Section에 포함되기 때문에 선언만 하더라도 0값으로 초기화되며 (이 과정은 운영체제에서 진행) 지역변수는 stack에 잡히므로 초기화 하지 않으면 garbage 값이 잡힘 따라서 책에서의 표현이 정확하지는 않다는 개인적인 생각이 있다
2. 변수의 형태를 자료형이라 하며 기본적으로 정수형과 실수형으로 나뉨. 
3. 변수에 const 를 사용하면 상수처럼 사용할 수 있다. -> identifier를 l-value로 다시 사용할 수 없다로 생각하자.
4. 예약어는 컴파일러와 약속된 단어이고, 식별자는 사용자가 만들어 낸 단어이다.

Scanf#

1. 키보드로 데이터를 입력할떄는 scanf함수를 사용하며 변수 앞에 &를 사용한다 -> 변수나 문자 하나를 입력할때는 Stack 혹은 Heap의 메모리 주소를 참조해야 하므로 address type을 붙혀주지만 문자열은 stream의 형식이므로 문자열의 첫 문자가 주소 값을 반환하기때문에 address type을 붙혀주지 않아도 된다.
2. 둘 이상의 데이터를 입력할때는 space bar, tab, enter로 각 데이터를 구분한다

Operator#

1. 결합 법칙 : 우선 순위를 가진 연산자가 여러개 있을때 c에서는 대부분의 연산자가 (Left to Right) 결합 법칙을 따름 but 대입 연산자나 삼항 연산자는 오른쪽 결합 법칙을 따름
2. sizeof 연산자는 괄호와 함께 사용하지만 함수는 아니다 -> 컴파일 될떄 이미 크기가 결정되기 떄문에 함수호출에 대한 오버헤드를 줄이기 위해 연산자로 설계되었다.
3. 복합대입 연산자의 우선순위는 대입 연산자와 같다
우선순위 연산자 설명 결합법칙
1 () 괄호 좌 -> 우
2 [], ->, . 배열 인덱스, 구조체 포인터 접근 좌 -> 우

IF#

1. cpu는 pipeline 방식을 활용해 여러 명령어를 동시에 처리하는데 분기(if) 가 발생하면 cpu는 다음에 실행 할 명령어를 예측해서 미리 준비한다. (분기 예측)  
2. 예측이 틀리면 pipeline을 비우고 다시 채워야하므로 성능에 손실이 발생할 수 있다.
3. 따라서 삼항 연산자 혹은 shift 연산자로 if문을 일부 대체 할 수 있다.

Function#

1. 함수 선언을 하면 함수를 만들지 않고도 함수의 형태를 미리 알릴 수 있다. -> c 는 컴파일러 언어이기 떄문에 위에서 아래로 컴파일되므로 정의된 위치보다 앞에서 함수를 사용하고자 한다면 프로토타입이 필요하기 때문에 함수 선언을 미리 해줘야한다.

Array#

1. 배열을 선언하면 많은 변수를 한번에 선언하는 효과를 볼 수 있다. -> 배열은 동일한 데이터 타입의 여래개의 변수를 연속된 메모리 공간에 저장하는 자료구조이다. 배열의 identifier는 고정된 메모리 주소를 가리키기떄문에 포인터 상수로 간주되며 이 주소를 다른 메모리 위치를 가리키도록 변경할 수 없다,
2. 배열의 주소값은 운영체제의 주소체계에 따라 달라지기떄문에 4byte 혹은 8byte의 크기를 가질 수 있다.
3. 포인터는 포인터 변수 배열은 주소값을 나타내므로 포인터 상수의 값을 가진다.
   
4. 배열 전체의 크기를 구할때는 sizeof 함수를 사용한다.
5. 정적으로 메모리를 선언할때는 stack 메모리에 할당되기때문에 메모리 해제를 해주지 않아도 되나 동적으로 메모리를 선언할때는 heap 메모리에 할당되기때문에 free or delete 를 사용하여 직접 메모리를 해제해야함.
Stack은 Frame의 성질 Heap은 list의 성질을 가지고 있다.
